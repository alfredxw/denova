# Mobile Workbench v2 设计规范

> 状态：设计决策已接受，实施未开始
>
> 日期：2026-08-03
>
> 范围：手机、紧凑宽屏/平板与桌面的统一工作台行为，重点定义移动端呈现

## 1. 最终结论

Denova 的移动端应当是一个能力完整、一次只显示一个主工作面的创作工作台。它不是桌面端的缩小版，不使用左右抽屉和底部 Dock 拼出伪多栏，也不是只能查看或审批的移动伴侣。

最终界面由一个稳定的黑白应用外壳承载：顶部栏负责定位当前工作对象，底部四入口负责一级导航，中间区域始终只承担当前任务。写作与游戏共享同一套导航规则、返回栈、保存语义和任务恢复行为；两种模式只在用户明确切换时改变，并分别恢复自己的工作现场。

手机上的核心导航是：

| 模式 | 入口 1 | 入口 2 | 入口 3 | 入口 4 |
| --- | --- | --- | --- | --- |
| 写作 | 正文 / Manuscript | 项目 / Project | Agent / Agent | 更多 / More |
| 游戏 | 故事 / Story | 剧情线 / Storylines | 资料 / Reference | 更多 / More |

“更多”顶部提供“写作 / Writing”和“游戏 / Game”分段切换。切换后关闭“更多”，恢复目标模式上次的一级入口、工作对象、输入草稿和滚动位置。进入任务、版本、Skills、Agents、自动化或设置等共享功能不会切换模式；这些页面打开期间只有“更多”保持一级高亮。

## 2. 设计目标

1. 用户在 320px 宽的手机上也能完成写作、Agent 协作、变更审阅、故事试玩、剧情分支和资料维护的完整闭环。
2. 任意时刻只有一个清晰的主任务，不让导航、输入框、工具栏和侧栏竞争空间。
3. 手机、平板和桌面使用相同的数据语义与业务行为，只改变内容如何排布。
4. 离开工作面、切换模式、旋转屏幕、短时断线或 PWA 被挂起后，用户都能恢复到可信的工作现场。
5. 所有用户可见文案、状态、错误和空状态同时提供中文与英文翻译。
6. 通用界面优先复用现有 shadcn/ui、Radix、TipTap、Lucide 和稳定内容宿主，不重复实现成熟交互。

## 3. 非目标

- 不保留旧版九图标底栏、项目/Agent 功能抽屉、底部 Agent Dock 或边缘打开手势。
- 不提供“旧版移动布局”、底栏任意重排或 Agent 呈现方式三选一等长期设置。
- 不要求手机同时显示编辑器、项目树、Agent 与 Diff。
- 不承诺完整离线工作区；断线能力只保护已经打开且可以安全编辑的内容。
- 不在这份设计中改变桌面端的视觉结构，但跨设备业务契约必须同步统一。
- 不把品牌、通知铃铛、全局搜索或模式开关塞回常驻移动顶部栏。

### 4.1 一级导航规则

- 任意时刻恰好一个一级入口高亮。
- 一级入口之间切换不压入返回栈；再次点击当前入口回到该入口根部，但不能清除草稿或内容状态。
- 详情、编辑、审阅和共享子功能压入统一返回栈。
- 共享功能不会改变创作模式；返回后回到“更多”，再返回才回到进入“更多”之前的主工作面。
- 模式切换是唯一会替换四入口集合的动作，必须由用户点击“更多”顶部的分段控件触发。
- 项目切换独立于模式切换。切换项目前先保存可保存内容；失败时留在原项目并显示具体错误。

### 4.2 “更多”工作面顺序

1. 模式切换分段控件。
2. 任务中心摘要：等待用户和失败计数；运行中只显示低干扰状态。
3. 当前项目能力：版本、项目设置；写作模式可在项目设置中进入书籍元数据。
4. 创作能力：Skills、Agents、自动化。
5. 应用能力：设置、帮助与版本信息。

系统通知是用户级偏好，默认关闭，不在首次启动时请求权限。应用内任务中心始终可用。

## 5. 共通应用外壳

### 5.1 顶部栏

顶部栏高度稳定并包含安全区。根工作面左侧不显示返回箭头；进入详情后左侧只显示返回。中间显示：

- 主标题：当前工作对象，例如章节、Agent 会话、故事或资料条目。
- 副标题：当前创作项目，可点击进入项目切换；长文本单行省略并提供完整可访问名称。
- 保存或连接状态：只在有意义时靠近标题显示，例如“保存中”“离线”“有冲突”。

右侧最多两个当前工作面的高频操作，使用 Lucide 图标和可访问名称；其余命令进入溢出菜单。顶部栏不常驻品牌、通知、搜索和模式切换。

### 5.2 底部一级导航

- 四项等宽，每项始终显示图标和文字，不能只显示图标。
- 触控目标至少 `44 x 44` CSS px，底部加入 `env(safe-area-inset-bottom)`。
- 标签不横向滚动；英文长标签用已确认的短词，不通过缩小字体硬塞。
- 等待用户或失败数量显示在相关入口上；运行中使用小型非闪烁指示，不显示无意义数字。
- 软键盘打开时整体隐藏，由当前输入控件接管底部区域。

### 5.3 表层与模态

- 确认、菜单、简短选择使用 shadcn/ui Dialog、AlertDialog、DropdownMenu、Popover 或 Sheet。
- 复杂列表、表单、日志、Diff 和配置编辑使用全屏子工作面，不把半屏 Sheet 当页面。
- 不在卡片内嵌套卡片。管理页面以分组列表和分隔线为主，卡片只用于真正独立的重复对象或状态摘要。
- 手机不使用左右边缘手势打开产品面板，避免与系统返回、浏览器导航和文本选择冲突。

## 6. 手机关键屏幕

以下线框只表达层级和占位，不规定最终字体或像素尺寸。

### 6.1 写作：正文

```text
+----------------------------------+
| 第二十二章                 [···] |
| 失落花园 · 已保存                |
+----------------------------------+
|                                  |
|  夜雨落在旧温室的玻璃上。        |
|                                  |
|  她在第三排花架后找到了那封信，  |
|  火漆已经裂开……                  |
|                                  |
|                    可滚动正文区  |
|                                  |
+----------------------------------+
| [正文] [项目] [Agent] [更多]     |
+----------------------------------+
```

点击标题打开“最近打开”选择面板；完整创作结构始终从“项目”进入。手机不显示桌面 Tab 栏，但每个已打开文档分别保留草稿、选区、滚动和撤销历史。

### 6.2 写作：项目

```text
+----------------------------------+
| 创作结构               [+] [···] |
| 失落花园                         |
+----------------------------------+
| [大纲]      [文件]      [搜索]   |
+----------------------------------+
| v 第一卷 · 雨城         42,310字 |
|   01 归途                 已完成 |
|   02 温室                 写作中 |
|   03 来信                   规划 |
| > 人物表                     ··· |
| > 世界设定                   ··· |
|                                  |
+----------------------------------+
| [正文] [项目] [Agent] [更多]     |
+----------------------------------+
```

“大纲”按卷、章节和规划文档组织，是默认分段；“文件”提供原始目录和高级文件操作；“搜索”覆盖正文、规划与资料。普通浏览不启用拖拽，只有明确进入排序状态才显示手柄。

### 6.3 写作：Agent

```text
+----------------------------------+
| < 第 3 次修订              [+]   |
| 失落花园                         |
+----------------------------------+
| 你                               |
| [第二十二章 · 12.4 KB      x]    |
| 请检查人物动机是否连贯。          |
|                                  |
| Agent                            |
| 我发现两处动机断裂……             |
| [工具调用 · 3 项]                |
| [文件变更 · 2 个 · 待审阅]       |
|                                  |
+----------------------------------+
| [添加上下文]  输入消息…    [发送]|
+----------------------------------+
```

这里只显示一个可恢复会话。点击标题进入全屏会话管理；新建、搜索、重命名和删除都在那里完成。普通的“正文 ↔ Agent”切换不附加任何内容，只有“询问 Agent”“讨论本章”等显式动作创建上下文交接条目。

### 6.4 Agent 变更审阅

```text
+----------------------------------+
| < 变更审阅                 [···] |
| 2 个文件 · 18+ / 6-              |
+----------------------------------+
| [chapter-22.md] [outline.md]     |
+----------------------------------+
|  41  她停在门外。                |
| -42  她不知道该不该进去。        |
| +42  她认出了门后的脚步声。      |
| +43  犹豫因此变成了恐惧。        |
|                                  |
| [选中行添加反馈]                 |
|                    单栏统一 Diff |
+----------------------------------+
| [撤销全部] [继续修改] [接受变更] |
+----------------------------------+
```

变更审阅是临时全屏工作面，不属于一级导航。按文件浏览单栏统一 Diff，反馈记录来源和大小；接受、撤销或继续修改后返回原 Agent 会话。

## 7. 关键流程

### 7.1 写作到 Agent，再回到正文

```text
正文选区
  -> 询问 Agent
  -> 检查并可移除“来源 + 用途 + 大小”条目
  -> 进入原会话或明确新建会话
  -> 发送
  -> Agent 后台运行
  -> 用户可切回正文继续编辑
  -> 返回 Agent 时从持久状态续接
  -> 有文件变更时显式进入变更审阅
  -> 接受/撤销/继续修改
  -> 回到原 Agent 会话或恢复原正文现场
```

任何普通页面切换都不得隐式把当前文件、历史日志或整个工作区加入模型上下文。上下文交接必须有来源、用途、版本、大小和可配置上限。

### 7.2 项目浏览到正文

```text
项目 > 大纲
  -> 点击章节
  -> 切换到“正文”并恢复该文档工作状态
  -> 编辑并持续保存草稿
  -> 返回“项目”
  -> 恢复原分段、展开节点、筛选和滚动位置
```

图片、JSON 等非正文文件留在“项目”内全屏预览，不错误进入正文编辑器。

### 7.3 故事回合提交

```text
用户选择建议或自由输入
  -> 建议仅填入输入框
  -> 用户明确发送
  -> 锁定回合上下文快照
  -> 创建运行并禁止重复提交
  -> 流式叙事稳定追加
  -> 检定、状态变化和图像任务分别更新
  -> 完成后形成不可变历史回合
```

生成期间保存的新导演规则或状态从下一回合生效。若要影响当前回合，用户必须明确停止并重新生成。

### 7.4 历史回合修改

```text
打开回合菜单
  +-- 目标是最新回合且无后续依赖
  |     -> 全屏回合修订 -> 保存修订记录
  `-- 目标后存在后续回合
        -> 明确“从此处创建分支”
        -> 原分支保持不变
        -> 在新分支编辑并继续故事
```

系统不得静默删除后续回合，也不得把旧后续接到已经改变的前提上。

### 7.5 后台任务恢复

```text
Agent / 自动化 / 图像 / 批量导入导出启动
  -> 注册来源项目与恢复目标
  -> 离开发起页面后继续运行
  -> “更多”显示低干扰运行状态
  -> 等待用户或失败时计入徽标
  -> 用户打开任务
  -> 保存当前现场
  -> 必要时切换来源项目
  -> 恢复到会话、审阅、日志或操作页面
```

短暂加载、保存成功、普通提示和版本更新不属于后台任务。

## 8. 导航栈与返回行为

顶部返回、Android 系统返回和浏览器历史必须使用同一逻辑栈。一次返回只处理一层，优先级固定为：

1. 收起软键盘并退出专注输入态。
2. 关闭最上层菜单、Popover、Sheet 或 Dialog。
3. 处理可执行配置的未保存草稿保护。
4. 退出全屏详情、编辑、导演台、关系总览或变更审阅。
5. 从“更多”子功能返回“更多”。
6. 在一级入口根部交还浏览器/PWA，由平台决定退出或返回站外历史。

一级入口互相切换不产生无限历史。浏览器刷新和 PWA 恢复后，应用应重建可解释的业务路由，不依赖仅存在内存里的模态层级。

## 9. 状态保存与恢复

| 状态范围 | 必须保存 | 清除条件 |
| --- | --- | --- |
| 创作项目 | 当前模式、两个模式的工作状态、最近对象 | 用户关闭项目或显式重置 |
| 模式工作状态 | 上次一级入口、当前对象、滚动、展开项、未提交输入 | 该模式被显式重置 |
| 文档工作状态 | 草稿、光标、选区、滚动、撤销历史、保存状态 | 文档明确关闭且草稿已处理 |
| Agent 会话 | 消息、输入草稿、滚动、运行、工具卡展开状态 | 会话删除 |
| 故事分支 | 当前回合、输入草稿、滚动、展开事件 | 分支删除或故事退出 |
| 管理列表 | 查询、筛选、排序、滚动、选中项 | 用户清除筛选或离开项目 |
| 临时表层 | 菜单、对话框、未提交确认 | 完成、取消或刷新 |

响应式层级变化只能移动稳定内容宿主，不能重新挂载编辑器、Agent 会话或故事舞台。现有 `StablePortalSlot` 思路可以复用，但业务状态不能依赖某个响应式组件是否挂载。

## 10. 保存契约

| 内容类型 | 示例 | 行为 | 离开保护 |
| --- | --- | --- | --- |
| 创作内容 | 正文、世界资料 | 持续保存本地草稿并同步；显示保存中、已保存、离线、冲突 | 有未同步或冲突时明确提示 |
| 即时偏好 | 语言、主题、字体、动效、内容密度 | 修改后立即保存并生效 | 保存失败时回退并提示 |
| 可执行配置 | Agents、Skills、自动化、模型、导演规则 | 在本地编辑草稿；完整校验后用户明确保存才生效 | 返回时继续编辑或放弃，不能静默应用 |
| 历史事实 | 故事回合、状态修订 | 通过提交、修订或分支流程创建审计记录 | 禁止无记录覆盖 |

配置项只增加长期有价值的偏好：系统通知、字体、动效、内容密度和场景图像策略。旧布局、底栏顺序和 Agent 布局不做配置。

## 11. 专注输入态与软键盘

### 11.1 共通规则

- 依据 `visualViewport`、焦点和实际可见区域判断键盘状态，不依赖固定超时。
- 键盘出现时隐藏一级导航；键盘关闭后恢复原入口和滚动位置。
- 输入框、编辑工具栏和一级导航不能同时堆叠在底部。
- 工具栏和输入框加入键盘上方与安全区补偿，旋转屏幕后重新测量。
- 不截断前台 thinking 或工具流；视图离开后仍由持久运行状态续接。

### 11.2 正文键盘工具栏

普通状态只显示撤销、重做、段落样式、粗体、斜体、插入菜单和收起键盘。低频格式能力进入菜单，AI 动作不常驻。

存在非空选区时，同一行原位切换为选区工具栏：格式、评论、询问 Agent 和更多。更多从当前可用 Skills 提供适用动作。取消选区后恢复普通工具栏，不再叠第二排，也不绘制与系统选择菜单竞争的浮层。

## 12. 断线与 PWA

断线期间允许：

- 阅读已经缓存的内容。
- 编辑已经打开的正文和输入草稿。
- 将修改作为绑定项目与基础版本的“待同步草稿”持久保存。

断线期间禁止：

- 提交 Agent 或故事回合。
- 控制后台任务或切换创作项目。
- 执行结构迁移、版本恢复或打开未缓存内容。

恢复连接后先做基础版本校验。远端未变化则同步；远端已变化则进入冲突审阅，不直接覆盖。界面持续显示“离线，等待同步 / Offline, waiting to sync”，产品文案不得宣称完整离线创作。

## 13. 三层自适应布局

分层依据是工作台容器的可用宽度，不是设备名称。以下数值是初始参考阈值，组件仍需校验自己的最小内容宽度：

- 手机层 S：容器 `< 640px`。
- 紧凑宽屏/平板层 M：容器 `640px - 1099px`。
- 桌面层 L：容器 `>= 1100px`。

| 能力 | 手机 S | 紧凑宽屏/平板 M | 桌面 L |
| --- | --- | --- | --- |
| 一级导航 | 底部四入口 | 同一四入口语义，可转窄侧栏 | 桌面活动栏，行为仍一致 |
| 主工作面 | 单工作面 | 单工作面；满足最小宽度时双栏 | 可调整多栏 |
| 正文文档 | 无可见 Tab | 默认无 Tab；可显示项目列表 + 正文 | 可见 Tab 与多栏 |
| 项目 | 列表 -> 全屏对象 | 大纲/文件列表 + 预览或正文 | 树、编辑器和辅助面板 |
| Agent | 单会话聊天 | 会话列表 + 当前聊天（空间足够时） | 会话、聊天与辅助详情 |
| 变更审阅 | 单栏统一 Diff | 文件列表 + 单栏 Diff | 可并排 Diff |
| 故事 | 叙事阅读器 | 阅读器 + 按需状态/导演摘要 | 多栏故事与导演工具 |
| 剧情线 | 分支纵向列表 | 列表 + 关系总览 | 完整关系图与详情 |
| 管理功能 | 列表 -> 全屏详情 | 列表 + 详情 | 多栏或表格 |
| 指针输入 | 44px 触控目标 | 粗指针仍保持触控尺寸 | 精细指针增强悬停和快捷键 |

只有在两栏都满足最小宽度时才能升级布局。例如会话列表至少约 280px、聊天至少约 480px；不满足就退回单工作面。跨层时不得改变当前任务含义或导航结果。

## 14. 视觉规范

- 应用背景使用纯白/近白或近黑/黑的单色体系，页面区块不做漂浮卡片。
- 红、黄、绿只表达危险、等待和成功等稳定语义，并同时配合图标与文字。
- 不使用渐变、氛围光斑、模糊大图或大面积品牌色区分写作与游戏。
- 游戏表现力来自真实场景图像、角色头像、叙事排版、检定和状态内容；正文不覆盖在场景图像上。
- 场景图像存在时按稳定宽高比预留，清晰展示并支持全屏查看；不存在时保持完整纯文本体验，不显示装饰占位。
- 工具型界面保持安静、紧凑、易扫描。面板内标题使用适配工作区的字号，不使用营销式大标题。
- 圆角不超过现有设计系统规范；重复列表优先分隔线，不把每一行都做成卡片。
- 不随视口宽度缩放字体；长标题换行或省略，任何文本都不能遮挡操作。

## 15. 双语、无障碍与触控

### 15.1 双语

- 所有导航、按钮、状态、错误、空状态、确认、任务类型和通知都必须有 `zh-CN` 与 `en-US` 键。
- 英文标签按真实最窄宽度验收，不以中文能放下作为完成标准。
- 日期、数字、字数、复数和快捷键提示使用本地化格式，不拼接句子。
- 屏幕同一时刻显示用户选择的语言，不把中英文同时堆在控件里。

### 15.2 无障碍

- 顶部栏、一级导航、主区域和补充区域使用正确语义；当前入口使用 `aria-current`。
- 图标按钮必须有可访问名称和 tooltip；状态不能只靠颜色。
- 所有 Dialog/Sheet 正确管理焦点、标题和关闭，返回后焦点回到触发控件。
- 动态任务状态使用低干扰的 live region，只播报需要用户行动的变化。
- 支持系统字体放大到 200%、屏幕阅读器、键盘导航和 `prefers-reduced-motion`。
- 正文、故事和 Diff 的阅读顺序必须与视觉顺序一致。

### 15.3 触控

- 高频触控目标至少 `44 x 44` CSS px，相邻危险操作保持足够间距。
- 长按只能作为可见行尾菜单的等价入口，不能承载唯一功能。
- 拖拽只在明确排序状态出现；普通滚动、选区和树展开不得触发结构变化。
- 横竖屏、安全区、浏览器地址栏收缩和虚拟键盘变化都不能造成底部控件重叠。

## 16. 建议模块边界

当前 `WorkbenchShell.tsx` 约 966 行，`ModeRouter.tsx` 约 1232 行，已经同时承担桌面布局、移动导航、模式路由、业务数据适配和大量功能组合。实施时不能继续把新状态和条件分支堆进这两个文件。

建议按职责演进，路径可根据现有 feature 结构微调：

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `features/workbench-navigation/` | 跨设备路由语义、模式状态、统一返回栈、可恢复目标 | 具体页面渲染 |
| `features/mobile-workbench/` | 手机/紧凑外壳、顶部栏、四入口、专注输入态、响应式组合 | Agent、编辑器或游戏业务 |
| `features/tasks/` | 后台任务模型、来源项目、聚合状态、任务中心和恢复契约 | 具体运行日志 UI |
| `features/context-handoff/` | 来源、用途、版本、大小上限和可移除交接条目 | 自动猜测上下文 |
| `features/writing/` | 正文工作面、项目创作结构、文档状态适配 | 工作台全局导航 |
| `features/changes/review/` | 现有审阅能力的单栏/双栏响应式呈现 | Agent 会话生命周期 |
| `features/interactive/` | 故事舞台、剧情线、状态/资料、导演台各自边界 | 共通应用外壳 |

具体拆分原则：

1. `ModeRouter` 收敛为路由与数据适配层，写作、游戏和共享能力分别组合，不继续内嵌页面实现。
2. `WorkbenchShell` 只组合应用外壳和稳定内容宿主，桌面活动栏与移动四入口由不同 presentation 组件实现。
3. 复用现有 `StablePortalSlot` 保持编辑器和会话宿主稳定；`AdaptiveSurface` 扩展为容器能力判断，而不是再增加全局 `isMobile` 条件。
4. 旧 `WorkspaceMobileLayout` 和 `MobilePaneHost` 中承担一级项目/Agent 抽屉的部分在新外壳稳定后删除；Sheet 只保留给短表层或局部选择。
5. 纯路由状态、保存契约和分支规则写成穷尽类型与独立测试；不要用含义不清的布尔值把模式继续塞进大型 props 接口。
6. 使用现有 shadcn/ui、Radix、TipTap、Lucide、react-virtuoso 和 Diff 依赖，不重新实现对话框、菜单、虚拟列表、编辑器或差异算法。

## 17. 不兼容变化

Beta 版本直接替换旧移动布局，不保留兼容开关。发布说明必须明确列出：

- 九图标或动态数量底栏改为每模式固定四入口。
- 项目与 Agent 不再作为左右抽屉，也不再支持边缘打开手势。
- 移动编辑器不再显示 Tab 栏；文档通过标题最近列表和项目工作面切换。
- Agent 不再作为编辑器底部 Dock 或并排面板，而是全屏单会话工作面。
- 模式开关移到“更多”顶部；点击任何共享一级菜单都不能自动切换模式。
- “书籍/workspace”逐步统一为顶层“创作项目”，书籍只保留为写作成果身份。
- 历史故事回合存在后续依赖时，修改必须创建新分支。
- 当前状态修改改为有审计记录的状态修订。
- 可执行配置不再边改边生效，必须校验并明确保存。

涉及项目命名、API、持久化、导入导出或会话恢复的数据迁移必须先备份并提供可回滚路径。

## 18. 分阶段实施顺序

### 阶段 0：锁定行为契约

- 为模式切换不被共享菜单触发、唯一一级高亮、统一返回栈和状态恢复补集成测试。
- 建立中英双语标签与空状态清单。
- 定义项目、后台任务、上下文交接和保存状态的稳定类型。

### 阶段 1：新外壳与写作闭环

- 实现四入口外壳、对象型顶部栏、更多工作面和三层容器布局。
- 完成正文、项目大纲/文件/搜索、最近文档与专注输入态。
- 用稳定宿主验证旋转和跨层不重建编辑器。

### 阶段 2：Agent、交接、审阅与任务

- 完成全屏单会话、会话管理、显式上下文交接和后台续接。
- 完成移动单栏变更审阅与任务中心恢复。
- 同步桌面端的运行生命周期和跨项目边界，避免移动专用语义。

### 阶段 3：游戏完整闭环

- 实现叙事阅读器、提交时快照、场景图像任务和导演台。
- 实现剧情线列表/关系总览、分支创建、当前状态与世界资料。
- 完成回合修订和状态修订审计。

### 阶段 4：共享管理与断线恢复

- 把设置、Skills、Agents、自动化和版本改为列表到详情。
- 完成待同步草稿、冲突审阅和 PWA 恢复。
- 加入默认关闭的系统通知偏好。

### 阶段 5：移除旧实现并发布

- 删除旧抽屉、Dock、九入口底栏、边缘手势和临时开关。
- 完成迁移、双语、无障碍、性能与全矩阵验收。
- 更新前端版本、`CHANGELOG.md`、`README.md`、`README.en.md`、Git tag 和 Release notes。

## 19. 验收矩阵

### 19.1 视口

| 宽度 | 代表状态 | 必测方向 |
| --- | --- | --- |
| 320 | 最窄支持手机 | 竖屏，短高度 568px |
| 360 | 常见窄手机 | 竖屏 |
| 390 | 主设计基准 | 竖屏与横屏 |
| 430 | 大屏手机 | 竖屏与横屏 |
| 768 | 平板/紧凑宽屏入口 | 竖屏与横屏 |
| 1024 | 紧凑宽屏上限 | 竖屏与横屏、粗/精细指针 |
| 1280 | 桌面层 | 宽屏与容器收窄 |

每个关键流程至少覆盖 `zh-CN`/`en-US`、light/dark、默认文本/最长真实文本、正常数据/空数据/错误数据。

### 19.2 布局验收

- 顶部标题、保存状态、两个操作和返回按钮无重叠。
- 四个导航标签完整可辨，只有一个入口高亮，安全区不吞掉控件。
- 键盘打开后一级导航消失，编辑工具栏或输入框恰好占用一层底部区域。
- 200% 字体下命令可达、正文可读、列表不横向溢出。
- 横竖屏和 S/M/L 跨层后，草稿、选区、滚动和撤销历史保持。
- 长英文、长项目名、长章节名、长 Agent 会话名和长任务来源都不会遮挡相邻操作。
- 无场景图像时没有空洞占位；有图像时比例稳定、可完整查看。

### 19.3 行为验收

- 点击版本、Skills、Agents、自动化或设置不会改变写作/游戏模式。
- 写作和游戏分别恢复自己的上次一级入口与工作现场。
- 普通进入 Agent 不自动附加当前文档；显式交接显示来源、用途、版本和大小。
- 离开 Agent 后运行继续，恢复时消息、工具结果和状态不丢失。
- 跨项目任务不会把结果注入当前项目，恢复前执行保存保护。
- 变更审阅不会自动抢占前台；完成后回到原会话。
- 历史回合修改创建分支，原分支及后续不变。
- 当前状态修改产生可撤销的审计修订，不改写世界资料。
- 断线草稿绑定基础版本，重连冲突不会覆盖远端。
- Android 返回、顶部返回和浏览器返回对相同状态产生相同结果。

### 19.4 可访问性与性能验收

- 使用键盘、屏幕阅读器和粗指针完成所有核心流程。
- 焦点不会落入隐藏工作面，关闭表层后回到触发点。
- `prefers-reduced-motion` 下无非必要动画，流式生成不造成持续布局跳动。
- 长列表使用已有虚拟化能力，旋转和跨层不复制大型编辑器或会话树。
- 自动化测试单项不超过 1 秒；完整真实流程使用集成/E2E 测试而不是堆低价值字段断言。
