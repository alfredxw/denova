## 1. 判定标准

本审计不以类型名、package 路径或旧测试是否仍存在作为等价证明。每项能力必须同时核对：

1. **Interface**：调用方仍能表达同一需求，配置默认值、错误模式和顺序约束明确。
2. **策略**：阈值、原子边界、保护规则、优先级、缓存策略和失败语义没有无意弱化。
3. **持久化**：canonical 数据、投影、receipt、CAS/revision 和幂等身份有唯一 durable authority。
4. **恢复**：进程重启、工具执行窗口、canonical commit 窗口、交互等待和结构变更均可确定恢复。
5. **展示与观测**：Writing/Game 的 UI、Diff、实时工具输入、事件顺序和 trace 不丢失。
6. **验证**：测试必须穿过当前生产 Interface；仅覆盖已经退出生产路径的旧 helper 不算证明。

差异处置只允许以下四种：

- **等价保留**：实现位置变化，但行为与约束均有当前生产路径证据。
- **明确改进**：行为不同，但严格覆盖旧能力，并降低双写、竞态、恢复歧义或缓存成本。
- **已修复**：审计发现迁移缺口，本轮补齐并增加回归测试。
- **确认删除**：只允许删除迁移期未发布的重复路径或已被更深 module 完整取代的协议；必须证明没有独立能力消失。

### LIFE-005 最终公开边界

长期保留的 lifecycle execution surface 只有 `Agent`、`Session`、`Run`、`Definition`、typed `Event`、Capability Interface，以及 typed recovery/status/commit receipt；公共 Model、Tool、Message、Stream 等组合 primitive 不在此限制内：

- frozen product-store restore plan、legacy host-effect codec 和旧 chat/tools Runner 均已删除；provider-neutral unknown-effect recovery、idempotency admission 与 typed invalid-input error 位于顶层 Interface。
- Denova binding、selector、control、cache key 只使用公共 `SessionKey`、`SessionSelector`、`Run` 与 typed error/status；产品代码无法导入 Go `internal` runtime。
- model/tool loop、actor、reducer、engine cancel 和低层 event sink 都是 package-private 实现；delegated Agent 通过公共 child Session/Run，不存在 in-memory Runnable 旁路。
- 外部 Store 只实现稳定的 `session.Store` contract；任何 checkpoint/index 优化必须是同一 canonical Log 的可重建 sidecar，不能根据 concrete type 改变 durable authority。

第一批删除不会损失 structural recovery：manual Compact/Remove 的 command-owned Definition/Compaction identity、CAS、receipt 与 crash recovery 已全部由公共 Session 持有；旧 descriptor 只会恢复第二份 Writing/Story canonical maintenance record，属于已删除的双 authority。工具 mutation 的唯一 authority则是 public `agent.Effect` canonical barrier；legacy `runtime.HostEffect` constructor/decoder 在生产中无调用。

因此 LIFE-005 的最终裁决为“已对齐”：对外组合能力足够自由，但固定生命周期阶段和 durable state machine 不再作为可替换零件泄漏。

## 5. 当前已确认的架构原则

- Agent Session 是 transcript、cleanup、checkpoint、failure fuse、structural recovery 的唯一 durable authority；Writing Session 与 Game Story 均已无可推进的 maintenance record、codec、journal、projection 或 reconcile API，产品仅保留只读公共状态投影。
- Denova Adapter 只提供产品 canonical source、opaque cursor、product commit/effect 和展示投影，不创建第二份可推进的 checkpoint。
- Tool Result Cleanup 是独立的可逆 model-context projection；普通 cleanup 与 checkpoint 每个 model step 最多持久化一个。hard overflow 可先临时收缩 recoverable body，但只提交 checkpoint。
- raw transcript 不因 cleanup 或 compaction 删除；remove/clear 通过 marker/revision 恢复有效上下文。
