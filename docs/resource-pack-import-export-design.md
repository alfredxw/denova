# 资源中心与资源包交换

状态：当前实现约定。本文将原设计中的产品决策与已实现行为合并；代码、测试及 AGENTS.md 是长期不变量的事实源。范围之外的能力列在末尾，不作为现有 API 的承诺。

## 产品定位

「资源中心」合并原市场与扩展，是与写作、游戏并列的共通一级目的地，提供发现、添加、管理与更新。资料库、创作方案和 Skills 等模块继续负责各自内容的编辑与使用；插件和游戏的启停、权限、模型绑定、设置及运行状态在资源中心管理。无需先打开作品，也不引入额外全局模式。

界面统一使用以下概念：

- **创作方案**：管理可复用的叙事风格、图像方案、游戏规划和状态系统等配置，供写作与游戏选用；各类型独立编辑和选择，不表示一键应用整套配置。
- **资源包（Package）**：资源中心中获取与分发的单位，可包含一种或多种资源；包内内容仍由创作方案、资料库、Skills 等对应模块编辑和使用，资源中心管理来源与更新。
- **资源（Resource）**：包内的具体内容。资源中心按内容类型分类，同一个包可出现在多个分类中；不再将包格式作为与内容类型并列的「资源包」分类。

页面包含：

- **发现**：搜索、类型与用途标签筛选、精选/最近更新排序、卡片/列表、分页及详情；返回列表保留筛选和位置。
- **二级导航**：发现资源、已添加（资源包／插件与游戏／可用更新）；内容类型目录始终显示，点击进入对应类型的发现列表，整个侧栏可收起。窄屏复用抽屉，选中目的地后自动关闭。发现标题旁显示注册点简称，点击直达注册点设置。
- **资源包**：按安装展示目标、来源、本地修改和远程更新状态；展开查看成员、更新策略、备份与扩展管理入口。
- **插件与游戏**：先选已安装扩展，再查看介绍、启停、配置、权限、模型绑定及运行状态；可以回到所属资源包。扩展只通过所属安装检查更新，混合包成员不可独立替换。未保存编辑器在切换资源页或一级菜单后保留；添加、更新与恢复前须先保存或取消草稿。
- **本地更新**：文件来源提供“从本地文件更新”，选择新版文件或扩展目录后进入同一更新计划，沿用原 Installation 与已确认授权；新权限仍须确认，不创建第二份拥有同一资源的安装记录。
- **可用更新**：仅展示已确认有远程更新的受跟踪安装。检查更新及更新策略仍复用已获取流程。
- **详情**：先展示索引元数据，点击获取后下载冻结预览。已安装的包提供明确的更新目标，优先选择当前项目，复用原安装记录进入更新预览；另行导入保留独立入口。资料与开场按集合选择，更新预览按条目展示处理结果和冲突选择。
- **工具栏**：统一“添加资源”入口接收 GitHub、HTTPS ZIP、本地文件与本地扩展目录，经同一冻结预览、权限确认与安装计划提交；组合导出沿用原有选择器。创建插件／游戏及导入源码进入工作台，开发能力不混入安装流程。搜索、排序和视图切换属于发现列表，提交收录放在侧栏底部。

没有安装记录的原创内容仍在原模块和导出选择器中，不伪造安装记录。「资源包」不等于全部本地资源；取消跟踪保留内容，删除内容由对应模块执行。本地安装与扩展管理查询独立于在线索引，索引不可用不会阻止本地配置、启停和卸载。

本次菜单整合只改变 UI 组合与暂态导航，不修改 Installation、Catalog、Release 或用户内容格式。本地目录仅作为预览输入，持久化仍是可移动的文件来源，不写入宿主绝对路径。

不增加统一可写 Resource Store，不将资料库改名为通用知识库，不统一卸载不同领域的内容，不增加账号、支付、评分或下载量。

## 官方索引

- 仓库：[alfredxw/denova-index](https://github.com/alfredxw/denova-index)。
- 默认读取地址：[index.json](https://alfredxw.github.io/denova-index/index.json)。设置中的「资源中心」支持替换为自托管 HTTPS 索引，也可恢复官方注册点。
- 公开浏览页：[Denova Index](https://alfredxw.github.io/denova-index/)。
- 每项一个 `entries/<id>.yaml`，只维护来源与可选精选标记，ID 由文件名校验。作者只维护包目录中的 `denova-pack.json`，其中 `package` 提供名称、简介、作者、默认语言、其他语言翻译、标签、使用说明与兼容条件；GitHub Actions 汇总生成 JSON 并发布 Pages，不手工维护第二份目录。
- 作者可提 PR 或使用仓库 Issue Form；维护者核实后收录，无独立内容管理后端。
- 示例源码维护在索引仓库 `examples/`，包含“照夜长河”修仙世界包，以及文本统计与“邻里来信”的扩展示例包。两份包均使用单一清单，包内资源可按用途选择，不重复收录内置 Skills。社区作者仍在自己的仓库维护实际内容。

生成目录包含中英文名称与简介、作者、格式、资源类型、用途、来源、更新时间与可选使用说明/兼容条件。资源中心统一从 `denova-pack.json` 读取展示信息，资源类型由 `resources` 推导，GitHub 更新日期取包目录的最近提交；不会要求作者每次更新内容再改 entry。远端单一清单从解析后的固定提交读取，只获取元数据，不执行第三方代码。目录每 6 小时及索引变更时重建；失败不发布，保留原有效目录。ZIP 来源登记同一份 `denova-pack.json` 的 HTTPS 地址，清单内提供 `package.updated_at`，不另设元数据格式。目录只用于发现，安装清单和权限仍以冻结预览为准。

客户端在用户访问发现页时获取索引，缓存一小时，支持手动刷新。用户级 `.denova/config.toml` 的 `[market] registry_url` 选择当前索引，写作和游戏共用；未设置时使用官方源。自托管源沿用相同 `index.json` 格式，可复用 denova-index 的生成工具。索引和包下载均不提供 Token 鉴权，包下载仍要求公开 HTTPS 来源。

缓存记录所属索引 URL；切换源立即重新加载，失败只保留同源有效缓存并提示过期，不回退到其他注册点。首次失败显示可重试错误。响应最多 4 MiB、5,000 个条目，重定向只允许相同 HTTPS origin。自定义源下隐藏官方提交收录入口。索引不授予订阅或执行权限，不承载包正文，也不触发后台扫描全网；已安装资源的更新继续使用安装记录中的来源，与当前 registry 无关。此次仅新增设置和可重建缓存字段，无需迁移已发布用户内容。

索引仓库使用 `alfred <xinggwang@gmail.com>` 提交；发布只依赖公开 npm 与 GitHub，不依赖内部基础设施。

## 资源与身份

| 资源种类 | 领域事实源及作用域 |
| --- | --- |
| `preset.narrative`、`preset.image`、`preset.game_planning`、`preset.events`、`preset.rules`、`preset.actor_state` | 全局预设库；导入为自定义资源 |
| `style.reference` | 全局文风参考库 |
| `skill` | 用户或指定 Project 的 Skills 目录；共享 Skill 可导出，不向其原目录导入；内置 Skill 不列入导出候选 |
| `lore.collection` | 指定 Book Project 的资料集合 |
| `game.openings` | 指定 Book Project 的开场集合 |
| `project.cover` | 指定 Book Project 的封面 |
| `project.creator` | 指定 Project 的创作规则 `CREATOR.md` |
| `extension.plugin`、`extension.game` | 平台管理的全局不可变发行 |

每次安装最多涉及一个 Project 和若干全局资源。作品名、DataRoot 及宿主绝对路径不参与持久化身份。持久化目标由稳定 `ProjectID` 加规范相对路径组成，运行时经 Registry 解析。

- **Package**：作者的交付单位，具有稳定包 ID。
- **Resource**：包内资源 ID、种类、载荷路径、明确依赖及附件。
- **Source**：用户确认的 GitHub 仓库/ref/path/commit，或 HTTPS ZIP 地址；本地上传记录文件名。
- **Installation**：一次获取建立的来源、目标、更新策略和资源绑定，不保存第二份正文。
- **Binding**：包内资源 ID 到领域本地 ID 的映射、来源摘要、本地基线和 owned/reference 身份。
- **Release / Instance**：仍由扩展平台维护。安装发行不改游戏实例、存档或发行 pins。

新预设、资料及开场分配本地 ID，再重写已知类型的引用；Skill 保留名称规则并允许显式改名；扩展清单 ID 不能改写。每个本地资源最多被一个仍在跟踪的安装拥有。相同准确发行的已启用扩展可只读引用其他安装的资源；引用者不能覆盖它或改变授权。

## 包格式 v1

原生组合包为 ZIP，根目录包含 `denova-pack.json`：

```json
{
  "format": "denova.resource-pack",
  "schema_version": 1,
  "package": {
    "id": "example-writing-kit",
    "name": "Example writing kit",
    "version": "1.0.0"
  },
  "resources": [
    {"id": "voice", "kind": "style.reference", "path": "style.md"},
    {"id": "narrative", "kind": "preset.narrative", "path": "narrative.json", "requires": ["voice"]},
    {"id": "assistant", "kind": "skill", "path": "skills/assistant"},
    {"id": "game", "kind": "extension.game", "path": "game"}
  ]
}
```

`package` 可包含简介、作者和最低 Denova 版本。资源中心登记时还需提供 `locale`：`name`、`description`、`usage`、`compatibility` 用默认语言撰写，`translations` 仅提供其他语言的同名文本，避免重复默认语言。`tags` 与 HTTPS `cover` 可选；GitHub 更新时间从仓库推导，ZIP 则使用 `updated_at`。预览、安装记录与再次导出保留这份完整信息。只导入、不上架的资源包可省略资源中心展示字段。

单独的 Skill 或扩展上架时也由 `denova-pack.json` 列出该资源；原生 `SKILL.md`、插件或游戏清单仍负责自己的运行时定义，直接导入方式保持不变。`requires` 只引用当前包内资源；不下载跨包依赖，不从提示词推测依赖。

### 可选创作规则

资源包可以声明一个 `project.creator` 资源，`path` 指向非空 UTF-8 Markdown 文件。每包最多一份，不携带附件，也不能成为其他资源的必选依赖。分发时应在 `package.min_denova_version` 声明首次支持该类型的正式版本。

导出选择器展示当前项目的 `CREATOR.md`；导入默认不勾选，允许预览全文。用户选择目标项目（或新建作品）后，固定写入该项目根目录的 `CREATOR.md`，不叠加提示词、不自动合并。若文件已存在，包括新书初始化模板，必须明确勾选备份后替换。后续更新遵循下述按项比较规则，双方冲突时逐项确认；未选择或上游移除的规则继续保留；停止来源追踪不删除内容。另一个资源包不能接管仍受追踪的规则，需先停止原包追踪。

采用既有 ProjectID、相对路径、导入计划、并发校验、事务备份和恢复流程；上下文沿用原文件注入来源。计划阶段按目标项目现有 Agent 上下文片段限制（含指令封装）校验，超限报错，不截断。含该资源的安装不支持自动应用更新。不新增用户配置或规则存储，无需迁移 v0.5.1 用户数据。

### 新故事推荐默认项

清单可用顶层 `game_defaults` 推荐背景和创作方案，所有资源 ID 均引用本清单的 `resources`：

```json
{
  "game_defaults": {
    "narrative_style_id": "narrative",
    "image_preset_id": "illustration",
    "planning_template_id": "planning",
    "actor_state_id": "actor-state",
    "rule_system_id": "rules",
    "event_package_ids": ["events"],
    "default_background": {
      "resource_id": "lore",
      "item_id": "world",
      "asset_path": "assets/background.png"
    }
  }
}
```

各项均可省略。背景必须是已启用 Lore 条目关联的本地图片，文件同时列入该集合的 `assets`。导入时映射为真实本地资源、条目和素材 ID；未选择导入的资源不可采纳，事件包按完整列表替换，不与已有列表拼接。

普通导入默认不采纳；从资源包创建新书时预选可用项，用户可逐项取消。已有书籍的默认项保持原样，只有显式勾选才替换。确认计划显示采纳项及覆盖提示，配置修改复用导入事务、并发校验与备份，不纳入包拥有的文件基线。已获取页可再次采纳，新故事表单也可将当前资源选择保存为本书默认项或清除默认项。

采纳结果保存在 `stores/<store_dir>/config.toml` 的 `game_creation_defaults` 中，仅属于该 Project，不进入用户全局配置。字段缺省沿用原创建行为；空资源 ID（规划模板除外）、空事件列表和背景 `mode: "none"` 表示明确不使用。此处只保存资源选择，不保存模型、权限、自动生图等运行偏好。

新故事创建前读取一次，显式输入优先，然后将选择写入既有 Story journal。已开始故事、扩展预览和更新资源包不重新继承书籍默认项；引用的资源内容仍遵循原有资源更新规则。缺失资源需用户修正或清空，不静默换成其他方案。导出已获取包时保留仍包含在导出选择中的推荐项。此功能为可选新增配置，无需迁移 v0.5.1 用户数据。

载荷规则：

- 普通预设使用可移植字段白名单，领域服务负责最终校验。叙事的 `style_refs`/`style_rules` 与规则的状态预设引用按包内资源 ID 重写。
- Lore 使用 `lore.collection`，开场白使用 `game.openings`：一个 `path` 指向 `{ "version": 1, "items": [...] }`。集合内每项保留稳定 `id`；Lore 保留内容、分类、关键词与加载方式，开场白保留 `title` 和 `content`，不携带运行时路径、来源记录、模型配置或时间戳。集合是一项资源，256 项资源限制不计入内部条目；文件大小仍受统一归档上限约束。
- 附件沿用每项的 `materials.entries`，本地文件用 `asset_path`，远程引用用 `url`；封面使用 `cover_asset_path` 或 `cover_url`。本地文件必须列入资源 `assets`，共享文件仅分发一份。
- 安装记录保存集合内源 ID 到项目 ID 的映射和逐项内容基线。整体选择、逐项预览，更新时合并已知身份、保留上游删除项；本地单方修改保留，双方不同修改需逐项选择。再次导出已安装包时保留源条目 ID 和资源依赖。角色卡转换同样输出一份集合文件。
- 开场集合内每项包含 `id`、`title`、`content`；封面载荷使用 `asset_path` 指向声明的 PNG。
- Skill 是原有目录结构，保留 `SKILL.md` 和辅助文件。
- 扩展保留原生清单及准确发行字节，不混入开发源码、设置实例、授权、存档或构建产物之外的工作目录。
- 不导出凭据、模型账户、provider/profile 配置、运行记录或宿主路径。不执行包内安装脚本或构建命令。

支持直接输入普通 Skill ZIP/仓库、原生插件/游戏 ZIP/仓库以及本地 PNG/JSON 角色卡，无需全部强制套组合包。GitHub 源在预览时固定 commit；扩展按照声明的发行文件集合提取，缺少已构建文件时失败。

文件准入复用扩展平台：规范相对路径、跨平台文件名、拒绝符号链接/特殊文件、大小写冲突、目录重叠与依赖环。单文件最多 16 MiB，解包总量最多 256 MiB、10,000 个文件；HTTPS ZIP 下载沿用 Skills 的 32 MiB 上限。图片另校验格式和尺寸。

## 导入、更新与权限

手动导入流程为「来源 → 冻结预览 → 选择内容和目标 → 确认计划 → 提交」。资源中心详情只读取索引中的介绍、资源类别、使用说明和来源，不下载资源包或创建预览。用户点击获取后，导入弹窗下载并冻结内容，随后选择资源、目标并确认计划，不重复填写来源。

预览可列出多个候选包，用户一次选择一个；选择资源自动包含必要依赖。文件检查器查看已冻结的文本，最多显示 64 KiB，二进制只显示信息。预览有效期 24 小时，最多保留 32 个未过期预览；关闭释放未被待更新记录引用的预览。

计划保存在服务端，包含目标、动作、准确发行、授权和写入前提。普通计划有效一小时；提交按计划读取冻结内容，不重新下载，不再次调用模型。重复提交同一个已成功计划返回相同结果。

新导入默认复用同包同来源的已有全局资源，以及同名用户 Skill，确认计划标明复用；不覆盖现有内容，也不接管来源更新。可明确选择导入独立副本，预设和风格使用新身份，同名用户 Skill 自动添加数字后缀。扩展保持固定身份，沿用已有引用与发行校验。项目资源按目标书籍独立导入；替换已修改资源、现有封面或创作规则必须明确选择。其他安装拥有的项目资源不能直接抢占，需先回原安装处理或取消跟踪。覆盖前保留备份；不提供猜测式三方合并。上游移除或本次未选择的已有绑定保留本地内容，不自动删除。

更新沿用原 Installation 与本地 ID；比较上次处理的来源内容、上次应用的本地基线和当前双方内容：

| 本地 | 远端 | 行为 |
| --- | --- | --- |
| 未修改 | 未修改 | 无需修改 |
| 未修改 | 已修改 | 更新，保留身份与引用 |
| 已修改或删除 | 未修改 | 保留本地，不恢复删除内容 |
| 已修改 | 相同结果 | 记录已同步，不重写正文 |
| 已修改或删除 | 不同修改 | 保留待处理，逐项选择保留本地或备份后采用远端 |

Lore 和开场按条目判断；预设、风格、Skill 与扩展按完整资源判断。保留本地只确认已看过的来源状态，不把本地定制重置成上游基线；同一远端版本不重复提示，后续远端修改仍检测冲突。未处理冲突及依赖它的资源暂不更新，独立项可以提交。Skill 替换包含完整目录，并在提交时检查预览后新增的文件。时间戳不参与预设内容比较，文件提交仍使用精确版本校验。

上游新增内容由用户选择；上游删除仅标记并保留本地。资料内自行新增的条目不受更新影响。更新不会重新采用项目默认配置或修改已有故事。安装记录保存已审阅来源摘要，用于发现新增资源、包元数据及推荐配置变化；摘要不依赖安装路径或 Git commit。

| 更新策略 | 行为 |
| --- | --- |
| `manual` | 默认；只在用户主动检查时联网 |
| `notify` | 每日检查，展示状态，等待用户确认 |
| `auto_apply` | 仅纯预设、文风和 Skills 安装可用；按项应用无冲突更新，保留本地修改及待处理冲突；原选择及依赖集合不扩大、消费任务空闲时应用 |

插件、游戏、资料、开场、封面及包含这些内容的混合包只支持手动/提醒。自动更新复用待处理预览，在繁忙时延后，不反复下载或改变用户已选范围。检查失败记录检查时间并等待下一周期，不形成重试热循环。资源中心刷新、来源检查和安装更新是独立操作。

扩展由平台统一验证批次中的依赖和权限。最终确认对应准确发行；包不能自行授予新增权限。新安装启用，更新保留原启用状态。发布新的不可变发行不会改变运行中游戏的旧 pins；修改已在运行的同一发行授权需要先停止其消费者。预览与安装不启动扩展后端，Node 后端也不被描述为系统沙箱。

游戏安装后由用户配置并显式开始游戏。已有游戏使用新版继续走原有备份、兼容性检查及升级流程，资源事务不复制游戏进度。

角色卡复用既有转换器，产生一个 Lore 集合、一个开场集合、封面及兼容性报告。资源中心通用上传采用本地分类；原角色卡入口保留语义分类和新建作品选项，转换完成后冻结一次，再经同一事务提交。已有作品封面默认保留，明确选择后才替换。导出转换结果为 Denova 包，不承诺原卡无损回写。

## 导出与恢复

领域入口可预选当前资源，资源中心可跨模块组合选择。导出从原有库读取，自动补充已知文风、状态预设和平台插件依赖，缺少必要内容则失败。单个 Skill 或扩展可选择原生 ZIP；组合包使用稳定包 ID 与稳定包内资源 ID。

导出候选隐藏未修改的内置预设与内置 Skills。预设复用 `custom` / `builtin_overridden` 判定，恢复默认后重新隐藏；内置 Skills 只读，另存到用户或 Project 范围的副本正常显示。启用、禁用不影响导出资格；候选过滤不改变必要依赖的自动打包。

导出前生成冻结快照，确认页展示资源、依赖、文件数和大小；下载有效期一小时。后续编辑不改变已确认的文件。可保存导出定义作为下次的选择，不复制正文；删除定义也不删除内容。

安装记录可查看和下载提交前备份。恢复先生成计划，要求全部目标仍与原提交后的内容一致；后来发生编辑、设置或记录变化则拒绝覆盖。恢复也经过同一事务与扩展运行检查，不直接解压覆盖数据目录。

## 应用层与持久化

应用层入口为 `internal/app/resourceexchange`，前端共用流程位于 `web/src/features/market`。`ResourceCatalog`、Skills、Lore 与平台 Manager 保留领域所有权。

```text
.denova/resource-exchange/
  cache/market.json                   # 可丢弃的发现索引缓存
  previews/<id>/                      # 有界冻结输入与预览
  plans/<id>.json                     # 确认后的提交前提与待写内容
  installations/<id>.json             # 来源、策略、绑定和基线
  transactions/<id>.json              # 提交状态与 before-images
  exports/definitions/<package>.json  # 可复用的选择
  exports/previews/<id>/              # 有时限的导出快照
```

这些记录不替代预设、Lore、Skills 或扩展原有正文，不影响 Session canonical journal。未提交预览与计划不能被执行器当成已安装资源。

提交顺序：

1. 应用取得目标 Project 的变更租约，确认消费任务空闲；平台批次同时隔离运行 admission 和平台元数据变更。
2. 取得 Skills/Lore 的领域写入租约及所有目标文件的共享锁；核对全部内容版本，再写入持久事务意图与 before-images。
3. 提交领域文件、扩展安装指针/授权/继承设置及 Installation；任一步失败按 before-images 回滚。
4. 提交开始后不因客户端断连中止结算；记录最终状态后返回。

不可变扩展发行可在提交前发布到缓存，但没有安装指针不会成为当前发行。常规编辑与交换事务复用 `revisionfile` 的文件锁和版本校验，避免跨入口覆盖。

启动在领域服务和后台更新器之前恢复未完成事务。只有当前内容等于事务前或事务后内容时才自动回滚；发现未知外部编辑则停止启动，保留记录与文件供人工恢复，绝不覆盖未知修改。当前没有按目标隔离的图形化故障恢复界面。

## HTTP 边界

所有路径以 `/api` 为前缀；来源/文件下载和写入遵守现有认证及本机操作检查。错误由本地化 key 显示，诊断写入日志。

| 路径 | 职责 |
| --- | --- |
| `GET /resource-market/catalog`、`POST /resource-market/catalog/refresh` | 读取/刷新固定索引 |
| `POST /resource-exchange/previews`、`DELETE /resource-exchange/previews/:id` | 冻结或释放输入 |
| `GET /resource-exchange/previews/:id/files` | 检查冻结资源文件 |
| `POST /resource-exchange/plans`、`POST /resource-exchange/plans/:id/apply` | 生成计划并提交 |
| `GET /resource-exchange/installations` | 已获取及本地状态 |
| `POST /resource-exchange/installations/:id/check`、`/policy`、`/detach` | 检查、更新策略、取消跟踪 |
| `GET /resource-exchange/export-resources` | 从领域库读取可导出摘要 |
| `POST /resource-exchange/exports`、`GET /resource-exchange/exports/:id/download` | 冻结导出及下载 |
| `GET/PUT /resource-exchange/export-definitions`、`DELETE /resource-exchange/export-definitions/:id` | 保存、读取和删除导出选择 |
| `GET /resource-exchange/installations/:id/backups` | 列出备份 |
| `GET /resource-exchange/backups/:id/download`、`POST /resource-exchange/backups/:id/restore-plan` | 下载或计划恢复 |

模块旧扩展安装入口保留其权限确认界面，内部交由公共计划提交；Skills 与角色卡入口复用公共服务。不要继续从旧 Skills 来源文件启动另一套更新器。

## v0.5.0 数据迁移

首次加载将用户及可用 Project 的 `.denova-source.json` 转成 Installation，并在同一事务中备份、移除旧来源文件。仅原本明确开启自动更新的 Skill 保留 `auto_apply`，其余为手动。已修改内容保留，并标为需要人工处理；不迁移或修改 `~/.agents/skills`。

升级不改 Skills 正文。v0.5.0 不识别新 Installation；降级后原有远程来源/自动更新信息不可用，需停止应用，从 `resource-exchange/transactions` 中对应迁移事务的 before-images 恢复旧来源文件，并另行保留升级后的内容。迁移备份不是资源中心的一般“恢复安装”按钮，避免新版运行时重新出现两个来源事实源。

未发布的扩展来源字段统一转移到 Installation，不增加双写兼容层。

## 当前范围与后续能力

以下保持明确边界，不用临时状态模拟未实现能力：

- 通用资源包导入选择已有作品；需要新作品时先创建再导入。角色卡沿用原新建作品流程；创建作品与资源提交还不是同一持久事务。
- 角色卡直接输入为本地 PNG/JSON；需要远程分发时先导出转换后的 Denova 包。尚未提供远程原卡的稳定条目匹配与原位更新。
- 已获取页面进入对应 Project 和模块，尚未为所有资源实现精确选中某条内容。
- Lore 与开场白按安装记录中的成员检查本地修改，无关条目编辑不阻断更新；事务提交仍核对完整集合文件版本，防止计划生成后并发覆盖。开场集合复用相同的成员身份与冲突检查。
- 当前冲突处理是拒绝覆盖、显式整项替换、Skill 改名或取消跟踪；没有逐字段合并、任意类型副本重命名和逐项冲突跳过。
- 恢复异常需要保留文件并人工处理；没有目标隔离/故障修复向导。来源检查和安装是有界同步请求，不提供后台 job API。
- 不包含私有仓库认证、多索引、跨包自动下载、构建脚本执行、自动开局及个人存档交换。
