# Denova 大范围变更回归清单

## 1. 文档定位

本清单用于指导 Denova 所有大范围功能变更、核心组件重构、跨模块调整和发布前回归。它是一份长期维护的测试目录，不绑定某个分支、版本或具体实现。

适用场景包括：

- 改动 Writing、Game、AgentChat 等核心用户流程。
- 改动被多个模式复用的 Agent runtime、会话、工具、上下文、工作区、导航、设置或 UI 组件。
- 改动 API、配置、Project 身份、持久化格式、版本恢复或用户内容目录。
- 大量文件或多个 package 同时变化，局部测试不足以证明整体行为。
- 准备合并重要变更，或准备正式发布版本。

使用原则：

- 第 5 节“基础不变量”在每次大范围变更中都要通过。
- 其余章节按“真实影响域”选择，不要求无脑执行全部条目。
- 影响域根据行为、依赖和数据流判断，不能只看直接修改了哪些文件。
- 改动共享底座时，必须回归所有主要消费者；例如共享 Chat 改动至少检查 Writing、Game 和 AgentChat。
- 未执行项要记录“不适用”的理由；外部依赖无法验证时要记录风险、负责人和补测条件，不能静默跳过。
- 测试结论只对被验证的源码树有效。后续代码、依赖、配置或冲突修复改变相关行为后，需要重跑受影响条目。

## 2. 使用流程

1. 先阅读 Diff、调用链、配置和数据边界，填写第 3 节影响域。
2. 为每个选中域确定正常路径、失败路径、刷新/重启路径和数据保护路径。
3. 执行第 4 节自动化门禁和第 5 节基础不变量。
4. 执行所有选中功能域的检查项；共享能力按消费者矩阵分别验证。
5. 将结果保存为 `docs/tests/<change-name>-regression-<date>.md`，保留环境、证据、失败、修复和复验记录。
6. 如果测试中继续修改了实现，重新评估影响域，不只复验刚修复的单点。

常见联动关系：

- 共享消息列表、输入框或工具卡变化：选择“Agent runtime 与会话”，并在 Writing、Game、AgentChat 中分别验证。
- Project 身份或工作区事件变化：选择 Writing、Game、AgentChat/Files、数据恢复，检查前台与后台 Project 隔离。
- Context、Prompt 或 Tool Schema 变化：选择 Agent runtime、模型上下文与缓存，并覆盖所有使用该能力的 Agent 类型。
- 一级菜单或共享页面变化：选择导航域，同时从 Writing 和 Game 两个模式进入共享页面。
- 持久化、版本、删除或覆盖行为变化：选择数据恢复，并只在临时目录或完整副本上执行破坏性验证。
- API 或配置字段变化：同步选择前端消费者、后端服务、持久化和错误处理，不只验证一个请求。

## 4. 自动化与构建门禁

所有大范围变更至少执行：

```bash
git diff --check

go mod tidy
(cd agent && go mod tidy)

go test -count=1 ./...
(cd agent && go test -count=1 ./...)

go vet ./...
(cd agent && go vet ./...)

pnpm --dir web check:i18n
pnpm --dir web test
./scripts/build.sh
```

按风险追加：

- 并发、goroutine、Agent runtime、文件监听、持久化或异步生命周期变化：对相关 package 执行 `go test -race -count=1`；共享底座变化执行根模块与 `agent` 模块全量 race。
- 依赖、网络、安全、安装或正式发布变化：在两个 Go module 执行 `govulncheck`，并检查生产前端依赖。
- 前端布局或交互变化：运行相关组件测试，再用 Playwright 做可重复的系统验证。
- API、Agent 主流程、工具调用、上下文、版本恢复或工作区状态变化：优先增加或执行集成测试。

验收要求：

- [ ] `go mod tidy` 后只有预期的依赖文件变化，`git diff --check` 无错误。
- [ ] 所有相关测试、全量构建和静态检查通过；没有 race、panic、goroutine 泄漏或未处理 Promise rejection。
- [ ] 没有新增单项运行超过 3 秒的低效单元测试。
- [ ] 中英文 i18n key 对齐；用户界面按当前语言只展示中文或英文，不在同一交互中重复展示双语。
- [ ] `./scripts/build.sh` 完整结束，主程序、updater、前端和内嵌资源均成功生成。

## 5. 基础不变量

以下条目在每次大范围变更中都必须通过：

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| BASE-01 | 启动当前源码并打开已有 Project | 应用可加载，当前 Project、基础设置和主界面正确恢复，无启动崩溃或持续失败请求 |
| BASE-02 | 打开 Writing，切换章节并完成一次编辑保存 | 正文、目录和保存链路可用；不会覆盖其他文件或 Project |
| BASE-03 | 打开 Game，进入已有故事并完成一次输入；允许使用当前默认模型配置 | 输入、流式输出、正文/状态提交和刷新恢复可用；不会产生半回合 |
| BASE-04 | 显式切换 Writing 与 Game，再从两个模式进入一个共享一级页面 | 只有模式切换器能改变模式；共享菜单不自动切换模式；任何时候只有一个一级菜单高亮 |
| BASE-05 | 在两个 Project 间切换并分别读取内容 | API、缓存、会话、事件和写入按 Project 隔离，无跨 Project 内容污染 |
| BASE-06 | 刷新页面并检查最近操作 | 已提交内容、当前模式、活动页面和必要布局状态正确恢复，不重复执行副作用 |
| BASE-07 | 检查浏览器控制台、网络请求和服务端日志 | 无未解释 exception、重复 4xx/5xx、错误轮询、panic 或敏感信息泄漏；错误按当前语言展示并保留 Log ID |
| BASE-08 | 检查所有涉及用户内容的删除、覆盖或自动调整 | 用户内容优先保护；破坏性行为有明确确认、备份或可回滚路径，不静默丢数据 |

## 6. 测试数据与浏览器环境

前端测试分层：

- `pnpm --dir web test:playwright`：主测试层，同一套 Playwright Test 同时承载浏览器行为回归与核心 E2E。
- `pnpm --dir web test:browser`：浏览器交互回归，重点验证导航、响应式布局、主题与双语行为。
- `pnpm --dir web test:e2e`：连接隔离的真实 Denova 后端与本地确定性模型，覆盖写作保存和游戏回合持久化等核心链路。
- `pnpm --dir web test:unit`：辅助测试层，仅保留纯逻辑、解析器、状态转换和需要快速反馈的组件/Hook 测试。
- `pnpm --dir web test`：CI 与发布使用的完整前端测试入口，先跑 Vitest，再一次性跑全部 Playwright 项目。

Playwright 的后端数据固定写入 `web/test-results/runtime`，每次启动时重建；模型请求只发送到本地确定性服务。自动化测试不得复用开发者正在运行的 Denova 后端，也不得读取真实 `DENOVA_DIR`。

根据选中的影响域准备最小测试集，不必为无关变更创建所有数据：

- 全新的临时 `DENOVA_DIR`：用于首次启动、创建和安装类测试。
- 当前支持格式的已有用户数据副本：包含已完成会话、游戏故事、资料、预设和版本历史。
- 长篇 Book：包含大量章节、长正文、深层目录、长文件名和多份打开的文档。
- 普通目录 Project：与当前 Book 不同，用于 General Agent、Files 和 Terminal。
- 长会话：包含 thinking、多工具、大结果、SubAgent 和历史分页。
- 真实模型配置：协议或模型相关变化时，覆盖所有被改动的协议；图像变化时准备可删除的测试图片目录。

浏览器选择：

- 开发过程中用应用内 Browser 快速检查真实页面。
- 大型前端或核心组件改造，必须用 `control-in-app-browser` 回归 Writing 和 Game 主链路。
- 需要稳定、可重复断言时使用 Playwright。
- 依赖用户真实账号、登录态或现有浏览器会话时使用 Chrome。
- 已有前端进程时直接复用热更新；不要 kill 或再启动一套。后端变更使用 `scripts/restart-backend.sh` 更新可见进程。

涉及布局或用户交互时，至少检查：

- 宽屏与窄屏。
- light 与 dark。
- 中文与英文分别展示，界面跟随语言配置且不同时展示双语。
- 长文本、空数据、加载、失败和无权限状态。
- 键盘焦点、列表整行展开和关键操作可达性。

## 7. 导航、布局与本地化

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| NAV-01 | 从 Writing、Game 分别进入所有受影响的共享一级页面 | 不隐式切换模式；关闭共享页返回原模式；只有当前一级菜单高亮 |
| NAV-02 | 拖动受影响的一级菜单、侧栏或分栏，折叠后刷新并切换 Project | 只有真实用户调整会持久化；折叠不被拖动误触发；不同页面和 Project 不串值 |
| NAV-03 | 在宽窄屏切换受影响页面、Dialog、Tab 和抽屉 | 自适应布局可用，无页面级横向溢出或被遮挡的主操作 |

| NAV-05 | 用键盘遍历模式切换、菜单、列表和主要 Dialog | 焦点可见且顺序合理；模式状态互斥；列表点击父项整行即可展开/折叠 |

## 8. Agent runtime 与会话

共享 runtime 变化时，先选择所有实际消费者，再在每个入口至少完成一个真实 Run：Writing Agent、Game Agent、AgentChat、Config Manager、Automation、Image Agent，以及受影响的 SubAgent。

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| AGENT-01 | 观察 thinking、正文、工具名、参数增量、进度和结果 | SSE 实时到达；一次工具调用只对应一张卡；事件顺序、状态和最终正文正确 |
| AGENT-02 | 在受影响权限模式下执行无害的只读和测试写入 | 权限按会话固定；审批只由真实工具输入和规则决定，展示文案不参与安全判断 |
| AGENT-03 | Run 进行中刷新页面 | 同一后端进程内可附着活动 Run；不会创建重复 Run、重复消息或重复工具副作用 |
| AGENT-04 | Run 中输入追问，再分别测试发送和中断 | 发送与中断作用于准确会话和 Run；排队顺序稳定，不误伤其他会话 |
| AGENT-05 | 如果改动恢复语义，在工具前后分别重启后端并重试 | UI 明确表达终态；不会静默重放非幂等副作用；已完成内容和 canonical 数据仍在 |
| AGENT-06 | 创建含长 thinking、多工具和长结果的单个回合，刷新并向上分页 | 历史按完整用户回合展示，不截断末尾工具或正文，不错误提示还有更早消息 |
| AGENT-07 | 回答、取消并重复提交 Ask；必要时冷重启 | 只有一个规范结果；重复请求幂等；未知或失效交互给出明确错误 |
| AGENT-08 | 执行 read/glob/grep、Shell、edit/delete 等受影响工具 | schema、分页、计数、路径边界、部分成功和错误反馈正确；写入进入可审阅变更链路 |
| AGENT-09 | 如果改动 Goal/Plan，测试创建、编辑、暂停、清除和续跑 | 状态互斥关系正确，跨刷新恢复；仅正确的 Agent 能结束目标 |
| AGENT-10 | 运行有长输出的 SubAgent，分别在运行中和完成后打开详情 | 运行中跟随最新输出；完成后可从开头阅读并跳到底部；委派边界与来源稳定 |
| AGENT-11 | 测试短回复、长回复和用户主动上翻 | 短会话无大块空白；长会话默认到最新；主动上翻后不被强制拉回 |

## 9. 模型上下文与缓存

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| CTX-01 | 对比连续两轮无状态变化与一轮有状态变化的最终模型请求 | 稳定前缀保持不变；无变化不重复注入；变化只旋转必要边界，缓存命中不被无关 UI/元数据破坏 |
| CTX-02 | 检查所有新增模型可见片段 | 使用英文、产品中立；有明确 source、purpose、revision/identity；硬上限可配置且通常高于 50 KiB，不无提示截断 |
| CTX-03 | 修改 Project 指令、动态状态、Skill 或工具描述中的一个来源 | 只有对应上下文边界变化；其他稳定片段、工具 schema 和缓存前缀保持稳定 |
| CTX-04 | 触发受影响的 cleanup 或 compaction 路径并继续多轮对话 | 用户输入、assistant 正文、工具协议和必要状态不丢失；不会循环压缩、重写 canonical 历史或破坏后续调用 |
| CTX-05 | 产生超大可恢复工具结果并继续对话 | 完整结果安全保存；模型获得有界且可恢复的预览/receipt；UTF-8、Markdown 和来源标记完整 |
| CTX-06 | 使用超过 resident window 的长会话重启并继续 | 展示历史和模型上下文各自正确；最新输入与工具结果不丢；能从规范存储读取所需区间 |
| CTX-07 | 使用开发者模式或 trace 检查最终请求 | system、messages、tools、cache usage 与分叉点可审计；开发者模式关闭时不额外持久化完整敏感内容 |

## 10. Writing

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| WRITE-01 | 新建或打开 Book，必要时导入 `.txt` / `.md` | 目录、章节、正文和统计正确；失败不留下半成品 |
| WRITE-02 | 在长篇作品展开/折叠卷、定位章节、切换多文档与 Tab | 长列表可用；每个文档恢复自己的阅读位置，Tab 顺序和编辑状态稳定 |

| WRITE-04 | 执行普通/正则搜索与替换 | 预览、命中数和实际文件一致；不扫描 Denova 状态目录；失败不产生不可恢复的部分写入 |

| WRITE-06 | 在 Diff Review 筛选文件、切换文件、评论、接受/驳回、Undo/Redo | 编辑器状态稳定；新增/修改/删除/冲突正确；每个操作可逆且刷新后一致 |
| WRITE-07 | 在正文或 Lore 选区创建评论并提交给 Agent | 锚点和 revision 正确；反馈只消费一次；刷新或重连不重复出现 |
| WRITE-08 | 测试受影响的续写、章节确认、状态更新和会话 CRUD | 目标章节和状态边界正确；会话不串 Project，消息数和历史实时更新 |

## 11. Game

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| GAME-01 | 新建故事并完成开局 | 空故事可安全打开；正文、行动建议、状态和首回合原子落盘 |

## 18. 最终结论

放行前必须满足：

- [ ] 第 4 节自动化与构建门禁通过。
- [ ] 第 5 节基础不变量全部通过。
- [ ] 第 3 节选中的所有影响域均完成，未执行项有明确理由和风险记录。
- [ ] 浏览器、网络和服务端日志中没有未解释的高风险错误。
- [ ] 所有临时数据已清理；破坏性验证的目标、备份和恢复位置已记录。
- [ ] 如果是正式发布，第 17 节全部通过。

以下问题直接阻塞合并或发布：用户内容丢失或跨 Project 污染、共享菜单自动切换模式、Writing 或 Game 核心流程不可用、Agent 重复执行非幂等副作用、恢复流程不可回滚、模型上下文协议断链、构建/测试/race/安全检查失败，或发布包无法安装启动。
