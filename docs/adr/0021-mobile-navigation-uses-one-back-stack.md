# 移动端使用单一返回栈并移除功能抽屉边缘手势

移动端顶部返回按钮、Android 系统返回和浏览器历史必须映射到同一导航栈。返回顺序依次处理软键盘、最上层菜单或对话框、全屏子工作面、“更多”子功能，最后才在四个一级入口根部交还浏览器或 PWA；可执行配置存在未保存草稿时，由同一返回路径触发保存保护。

当前从屏幕左右边缘打开项目或 Agent 抽屉的自定义手势从移动方案中移除。边缘区域保留给平台返回、浏览器导航和文本选择等系统行为；产品功能通过可见入口进入，不能依赖隐藏手势。

## Status

accepted

## Considered Options

- 保留功能抽屉边缘手势：快捷但不可发现，并与平台导航和内容手势冲突。
- 每个功能自行处理返回：局部实现简单，但系统键、顶部按钮和浏览器历史容易产生不同结果。
- 单一返回栈：需要统一路由状态，但用户可以可靠预测每次返回的去向。
