# 软键盘打开时由当前输入控件接管底部区域

移动端在软键盘打开并聚焦正文、Agent 或游戏输入时进入专注输入态，暂时隐藏四入口一级导航。正文显示紧贴键盘的编辑工具栏，Agent 与游戏显示各自的输入框和发送操作；键盘关闭后恢复原一级导航，不改变当前入口、滚动位置、选区或输入草稿。

输入区域必须依据实际可见视口和设备安全区定位，不能把固定超时当作键盘状态，也不允许输入框、编辑工具栏和一级导航同时堆叠在屏幕底部。

正文的键盘工具栏只承载稳定的基础编辑命令：撤销、重做、段落样式、粗体、斜体、插入菜单和收起键盘。低频格式能力进入菜单；续写、润色或扩写等 AI 动作不常驻工具栏，而由用户选区、Skills 或显式上下文交接触发。

正文存在非空选区时，同一位置的键盘工具栏切换为选区态，提供适用的格式、评论、询问 Agent 与“更多”操作；“更多”从当前可用 Skills 中呈现选区能力。取消选区后恢复普通编辑工具栏，不额外叠加第二排工具栏，也不在正文选区旁绘制与系统选择菜单竞争的浮层。

## Status

accepted

## Considered Options

- 始终保留一级导航：入口持续可见，但会与键盘和输入控件共同挤压主内容。
- 整页随键盘自由滚动：实现简单，但固定输入框和 iOS 浏览器视口容易错位。
- 专注输入态：输入期间减少一个导航层，关闭键盘后无损恢复工作现场。
