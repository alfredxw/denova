# 创作项目取代书籍成为顶层内容边界

Denova 将“创作项目”定义为顶层用户内容容器，同时拥有写作内容、互动故事、资料、Agent 会话、配置和版本历史。“书籍”只表示项目在写作模式下的作品身份与成果，不再与 workspace 或整个项目互换使用；移动界面统一使用“项目切换”“项目设置”等文案。

当前代码和数据结构广泛使用 `Book`、`workspace` 与“书籍”表达同一边界，后续实施需要同步梳理前后端 API、持久化结构、导入导出、会话恢复和用户数据迁移。项目仍处于 Beta，可以优先统一边界，但任何不兼容重命名都必须提供备份或可回滚迁移，并在变更说明中明确列出。

## Status

accepted

## Considered Options

- 继续以书籍为顶层：沿用成本最低，但无法自然涵盖互动游戏及共享 Agent 能力。
- 同时使用书籍、项目和工作区：避免立即迁移，但用户文案与代码边界会继续漂移。
- 统一为创作项目：需要一次明确迁移，但能长期覆盖写作与游戏两种模式。
