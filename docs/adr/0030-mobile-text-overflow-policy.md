# 移动端文本溢出采用“短词保完整、长内容省略并补提示”策略

移动端窄屏上，文本放不下时的默认表现是单行省略号。实测发现两类问题：固定短词（如剧情线页标题“剧情线”、开场方式标签“书籍预设”）被布局挤压到只剩几十像素而显示省略号；长内容（目录树文件名、工作区路径、章节标题）省略后没有完整内容提示，用户无法查看全名。

因此移动端所有可截断文本统一遵循：固定文案与高频短词必须完整显示，必要时收缩同排的次要控件；用户内容（书名、章节、文件名、路径）允许省略，但被省略的元素必须携带完整内容提示（`title` 或可点击后可见完整值）。省略号是布局兜底，不是默认目标。

## Status

accepted

## Considered Options

- 全部文本换行显示完整内容：列表与标题会成倍增高，320px 下的单行工作台布局失衡。
- 全部缩小字号：可读性下降，且只能推迟截断，不能保证短词完整。
- 短词保完整、长内容省略并补提示：布局稳定，完整内容始终可查；被采纳。
